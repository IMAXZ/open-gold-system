# 架构说明

## 总体结构

本仓库采用单仓库结构，按“前端应用 + 后端实现 + 契约 + 部署”拆分：

- `apps/web` 负责图表展示和用户交互
- `backend/java` 提供 Spring Boot 版本后端
- `backend/dotnet` 提供 ASP.NET Core 版本后端
- `contracts/openapi` 用于沉淀共享接口契约
- `deploy/docker` 提供 `.NET` 与 `Java` 两套容器化部署方式

## 当前角色划分

- 前端：消费 `/api` 接口，展示金价历史与统计信息
- Java 后端：保留同业务能力的 Spring Boot 实现
- .NET 后端：当前默认主实现，具备更完整的测试与部署配套

## 关键设计约束

- 两套后端应尽量保持相同的接口路径、参数和返回语义
- 前端不应依赖某一套后端的私有行为
- 配置优先，避免把环境差异硬编码进前端或后端
- 部署脚本默认围绕 `.NET` 主实现维护

## 后续建议

- 为共享接口补充正式的 OpenAPI 文档
- 明确“主实现/备选实现”的维护策略
- 逐步统一 Java 与 .NET 的配置项命名和默认值
